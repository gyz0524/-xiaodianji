# 部署自己的小店记

以下流程创建你自己的新站点和网址，不需要原作者的账号或站点信息。

## 方法一：手动上传构建文件

1. 下载或 Fork 源码，在自己电脑上安装 Node.js。
2. 在项目根目录运行：

   ```sh
   npm ci
   npm test
   npm run build
   ```

3. 打开 [Netlify](https://app.netlify.com/)，使用自己的账号注册或登录。
4. 使用平台的手动部署入口，例如 [Netlify Drop](https://app.netlify.com/drop)，上传新生成的 `dist` 文件夹。
5. 平台会提供属于你的 HTTPS 网址。首次联网打开，确认页面完整加载后，再测试离线打开。
6. 在自己的手机录入一项测试记录，关闭重开，并导出一次备份，确认文件管理里能找到 JSON。

`dist` 内应直接包含 `index.html`、`assets`、`sw.js`、`manifest.webmanifest` 等。部署上传 `dist`；开源仓库上传源码，两者用途不同。

平台可提供默认子域名，不必一开始就购买域名。可用套餐、额度和地区网络表现以平台实际情况为准。

## 方法二：从自己的 GitHub 仓库部署

1. 将源码上传到自己的 GitHub 仓库，或者 Fork 本项目。
2. 在自己的 Netlify 账号创建新项目，选择从 Git 导入，只选择你要部署的仓库。
3. 构建命令填写 `npm run build`，发布目录填写 `dist`，Node.js 选择 24。
4. 本项目的 `netlify.toml` 已写好通用构建参数，没有任何现有站点 ID。
5. 平台会部署你的新项目。以后对部署分支的更新可能自动触发发布，按自己的流程管理合并权限。

本源码不包含自动部署的 GitHub Actions，不需要向仓库填写 Netlify Token。Git 托管集成使用你自己授予平台的仓库权限。

## 后续更新

手动部署时，重新构建并将 `dist` 上传到自己原有站点的部署页面。保留正式域名，不要每次更新都换成新站点。更换域名前，先从旧网址导出数据，再到新网址导入。

## 离线、桌面入口与数据

- Service Worker 需要 HTTPS 或 localhost。手机访问局域网 HTTP 地址不能保证离线或安装功能正常。
- 添加到桌面或收藏后，仍要固定使用同一浏览器和网址。
- 网页文件存放在托管平台；商品和库存存在用户手机浏览器里，不会因为托管而自动拥有云备份。
- 不同人的浏览器各自保存记录。开源和公开网址不等于公开用户浏览器中的库存数据。
- 禁止把自己店里的 JSON 备份放进 `public` 或 `dist`；放进去的文件可能作为静态文件被公开访问。

当前配置用于域名根路径，暂不提供 GitHub Pages 子路径部署教程。
